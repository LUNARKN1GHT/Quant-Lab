# 回测引擎

**代码**：[quant/backtest/engine.py](../quant/backtest/engine.py) & [quant/risk/metrics.py](../quant/risk/metrics.py)

## 模块功能

基于持仓矩阵和收益率矩阵做逐日**向量化**计算，避免逐行循环，适合因子研究阶段的快速验证。绩效评估由[quant/risk/metrics.py](../quant/risk/metrics.py)独立承担，引擎值负责生成日度收益序列。

## 核心概念

- **持仓矩阵**：$shape = (日期，股票)$，每行是当日各股票的权重，行和通常为1。
- **收益率移动位**：用 $t$ 日持仓对应 $t + 1$ 的收益，防止“用未来信息建仓”的前视偏差。
- **换手率**：相邻两日持仓变化的绝对值之和，直接决定手续费摩擦成本大小。
- **再平衡**：只在调仓日更新权重，非调仓日向前填充——模拟真实持仓“不动”的状态。

## 实现要点

- `shift=-1` 方向容易搞反，向前移是“今天的仓位赚明天的钱”，向后移才是未来的数据。
- 手续费按换手率的**一倍** `commission_rate` 扣除（单边）。若要模拟双边摩擦（买入+卖出各收一次），应传入 `commission_rate=0.0006`（即万三 × 2）。
- `rebalance()` 用 `resample().last()` 取每个周期末的信号，再 `ffill`；若信号在周期内有多条，只保留最后一条。

## 局限与边界

- 不模拟滑点、涨跌停、流动性限制，实盘摩擦大于这里的手续费估算
- 权重归一化需调用方保证，引擎不做检查
- 不支持做空。负权重在数学上可行，但国内基金、股票市场是不允许做空的。
- 不处理停牌股票（持仓矩阵里的 NaN 会直接传播到收益序列）

## 与其他模块的关系

- 上游：`quant/factor/` 各因子模块输出 signal 矩阵，需由调用方归一化为持仓权重后传入
- 下游：`backtest()` 返回的日度收益序列直接传给 `quant/risk/metrics.py` 计算 Sharpe / MaxDrawdown 等指标
- `rebalance()` 通常在 `factor_strategy.py` 中调用，在传入引擎前先降频信号
