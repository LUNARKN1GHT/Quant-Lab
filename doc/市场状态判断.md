# 市场状态判断（Regime Detection）

**代码**：[quant/regime/detector.py](../quant/regime/detector.py) · [quant/advisor/position.py](../quant/advisor/position.py)

## 模块功能

判断当前大盘处于哪种市场环境（牛市 / 震荡 / 熊市），为仓位管理提供依据。

这是整个控仓系统的"开关"——选股能力再强，在熊市满仓也会亏损。Regime 的输出直接决定底仓比例，是 `advisor/position.py` 三层乘数中权重最大的一层。

---

## 三态模型

| 状态 | 含义 | 默认底仓比例 |
| --- | --- | --- |
| **BULL** | 趋势上行，多数股参与上涨 | 100% |
| **RANGE** | 趋势不明或多空拉锯 | 60% |
| **BEAR** | 趋势下行，波动放大或宽度收窄 | 20% |

默认比例由 `Config.regime` 中的 `bull_scale / range_scale / bear_scale` 控制，可在配置文件中修改。

---

## 三个信号的逻辑

`detect_regime()` 综合以下三个信号逐日判断：

### 1. 趋势信号（Trend）

$$\text{trend}_t = \frac{\text{等权指数}_t}{\text{MA}_{120}(\text{等权指数})} - 1$$

以全部成分股收盘价的横截面均值作为"等权指数"，计算其相对 120 日均线的偏离幅度。

- 偏离 > 0（价格在均线上方）→ 趋势向上
- 偏离 < 0（价格在均线下方）→ 趋势向下

**为什么用等权指数而不是沪深300？**  
沪深300是市值加权，大盘蓝筹主导走势，可能掩盖中小盘的真实状态。等权指数对每只股票一视同仁，更能反映市场整体的参与度。

### 2. 市场宽度（Market Breadth）

$$\text{breadth}_t = \frac{\text{过去 20 日区间涨幅} > 0 \text{ 的股票数}}{\text{全部成分股数}}$$

统计近 20 日内价格上涨的股票占比。

- 宽度 > 0.55 → 多数股票参与上涨，牛市信号可信
- 宽度 < 0.45 → 多数股票在跌，熊市信号可信

**为什么需要宽度信号？**  
趋势信号只看"指数有没有涨"，但指数可能由少数权重股拉升，大多数股票其实在跌（结构性行情）。宽度信号过滤这种情况——真正的牛市需要多数股票共同上涨。

### 3. 波动率比值（Volatility Ratio）

$$\text{vol\_ratio}_t = \frac{\sigma_{20}(\text{等权指数日收益})}{\sigma_{60}(\text{等权指数日收益})}$$

短期波动率（20日）与长期波动率（60日）的比值。

- 比值 > 1.5 → 近期市场恐慌情绪明显高于历史均值，确认熊市信号

波动率比值只用于加强熊市判断，不单独触发 BULL。

---

## 判断规则

```txt
if 趋势向上 AND 宽度 > 0.55:
    → BULL

elif 趋势向下 AND (宽度 < 0.45 OR 波动率比值 > 1.5):
    → BEAR

else:
    → RANGE（默认）
```

用 `np.select` 实现，条件优先级从上到下，RANGE 是 fallback——既不满足 BULL 也不满足 BEAR 时，默认进入震荡。

## 与仓位建议的衔接

`detect_regime()` 的输出是 Regime 标签序列，传入 `compute_position()` 后映射为 `regime_signal`，与其他三个信号加权求和：

$$\text{仓位} = w_{\text{regime}} \cdot s_{\text{regime}} + w_{\text{vol}} \cdot s_{\text{vol}} + w_{\text{macro}} \cdot s_{\text{macro}} + w_{\text{sector}} \cdot s_{\text{sector}}$$

- **`regime_signal`**：BULL=1.0 / RANGE=0.6 / BEAR=0.2
- **`vol_signal`（波动率目标法）**：`target_vol / realized_vol`，截断到 [0, 1]
- **`macro_signal`（宏观景气信号）**：宏观 z-score 在 [-2, 2] 线性映射到 [0, 1]

四信号加权求和后截断到 `[min_position, max_position]`，权重默认为 0.4 / 0.3 / 0.2 / 0.1，可在 `configs/default.yaml` 中的 `signal_weights` 配置项调整。

## 参数设计的取舍

| 参数 | 默认值 | 影响 |
| --- | --- | --- |
| `ma_window` | 120 日 | 窗口越长越滞后，但信号越稳定；越短越灵敏但噪声多 |
| `breadth_window` | 20 日 | 控制"多少天内上涨"的统计窗口 |
| `vol_short / vol_long` | 20 / 60 日 | 比值阈值 1.5 是经验值，可针对不同市场调参 |
| `bull/range/bear_scale` | 1.0 / 0.6 / 0.2 | 直接决定各状态底仓，是最影响收益风险的参数 |

---

## 局限与边界

- **规则驱动，非概率输出**：判断结果是硬切换（BULL→RANGE 瞬间切换），不像 HMM 那样给出概率，对参数阈值敏感。
- **滞后性**：120 日均线天然滞后，趋势反转后往往要数周才能切换状态，牛熊转折点附近误判概率高。
- **等权指数的局限**：如果成分股里小盘股比例高，等权指数可能高估整体市场热度。
- **不区分行业结构**：整体市场 BULL，不代表每个行业都适合满仓——行业轮动信号（`quant/sector/`）是对 Regime 的补充，而非替代。

## 与其他模块的关系

- 上游：`quant/data/` 提供成分股收盘价宽表（`close`），`quant/macro/` 提供宏观景气指数（`macro_score`）
- 下游：`quant/advisor/position.py` 消费 Regime 标签，输出最终仓位建议
- Dashboard：`pages/2_market_state.py` 展示历史 Regime 走势与各状态天数分布；`pages/1_position_advise.py` 展示今日建议及三层信号分解
- 脚本：`scripts/regime_detection.py` 和 `scripts/backtest_regime.py` 验证不同状态下各策略的表现差异
