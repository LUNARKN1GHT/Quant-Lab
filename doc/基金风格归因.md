# 基金风格归因

**代码**：[quant/data/benchmark.py](../quant/data/benchmark.py) · [quant/fund/style.py](../quant/fund/style.py) · [quant/fund/portfolio.py](../quant/fund/portfolio.py)

## 模块功能

将一只基金的日收益回归到一组基准指数（沪深300、中证500），分解出：

- **各基准的 Beta 暴露**：基金对该基准的"跟随程度"
- **Alpha（年化）**：扣除基准贡献后的超额收益
- **R²**：基准对基金收益的解释力

这是判断一只基金"风格"的最基础工具——产品说明书说"成长型"还是"价值型"很容易，跑一遍风格归因看 CSI300 / CSI500 的 Beta 分配，得到的结论才有说服力。

## 一、数据层：`quant/data/benchmark.py`

基准指数的获取与缓存，沿用 `quant/macro/loader.py` 的设计：第一次调用拉取写入 `data/benchmark/{name}.csv`，之后离线读取，避免重复请求 akshare。

### 为什么放在 `quant/data/` 而不是 `quant/fund/`

基准指数将来也会被风险报告的 Beta / Alpha、策略对标基准的累计收益比较等模块使用，不是基金专属。归入数据层避免在多个业务模块重复实现 akshare 调用与缓存逻辑。

### 接口

```python
from quant.data.benchmark import load_benchmark, load_benchmarks

csi300_ret = load_benchmark("CSI300")           # 单个，pd.Series
df = load_benchmarks()                          # 全部已注册基准，宽表
df = load_benchmarks(["CSI300"])                # 指定子集
```

返回的都是**日收益率**（已除以 100），而不是收盘价——下游回归直接可用，不必再 `pct_change`。

### 数据源选择

默认走新浪源 `ak.stock_zh_index_daily(symbol="sh000300")`。东方财富的 `index_zh_a_hist` 在本地实测频繁 `RemoteDisconnected`（不是网络问题，是服务端拒绝），新浪源稳定可拉满 5900+ 个交易日。

### 新增基准的方法

在 `_BENCHMARKS` 字典里注册 `(名称, 新浪符号)`：

```python
_BENCHMARKS: dict[str, str] = {
    "CSI300": "sh000300",
    "CSI500": "sh000905",
    # "CSI1000": "sh000852",  # 后续扩展
}
```

新浪符号前缀：`sh`=沪市、`sz`=深市。注册后 `load_benchmarks()` 自动包含。

## 二、计算层：`quant/fund/style.py`

纯计算模块，不触碰 IO，输入由数据层提供。这种分层让单元测试可以构造任意基准数据，不依赖网络。

```python
from quant.data.benchmark import load_benchmarks
from quant.fund.style import fund_style_report

benchmarks = load_benchmarks()
report = fund_style_report(nav_series, benchmarks, name="某基金")
# {
#   "name": "某基金",
#   "CSI300 Beta": 0.65,
#   "CSI500 Beta": 0.28,
#   "Alpha（年化）": 0.045,
#   "R²": 0.87,
# }
```

### 回归实现

底层调用 `portfolio.style_attribution()`：

$$r_t^{\text{fund}} = \beta_1 \cdot r_t^{\text{CSI300}} + \beta_2 \cdot r_t^{\text{CSI500}} + \alpha + \epsilon_t$$

用 `np.linalg.lstsq` 求 OLS 解，输出系数（各 Beta）、截距（日 Alpha）、$R^2$。`fund_style_report()` 在外层做两件事：

1. **日 Alpha 年化**：乘 252，转成跟其他指标可比的口径
2. **结果展开**：把 `{"CSI300": 0.65, "Alpha（日）": 0.0002}` 拆成命名清晰的字段，方便 Streamlit DataFrame 展示

### 数据量保护

`style_attribution()` 在共同日期不足 60 时直接返回空字典，`fund_style_report()` 把这种情况翻译成 `{"name": name, "error": "数据不足"}`，调用方据此过滤展示。60 是经验阈值——更少的样本下 OLS 估计的 Beta 标准误过大，结论不可靠。

## 三、Dashboard 集成

`dashboard/pages/6_我的持仓.py` 的「投资建议」tab 有一个加载按钮：

```
📥 加载基准数据并计算风格归因
```

点击后：

1. 调用 `load_benchmarks()`（首次约 5~10 秒，之后走 CSV 缓存）
2. 对每只持仓基金跑一遍 `fund_style_report()`
3. 结果存入 `st.session_state["style_report"]`，下次切换 tab 不重算

结果以 DataFrame 展示，列为「名称 / CSI300 Beta / CSI500 Beta / Alpha（年化）/ R²」。

### 阅读方式

| 形态 | 含义 |
| --- | --- |
| CSI300 Beta ≈ 1，CSI500 Beta ≈ 0 | 典型大盘风格，跟随沪深300 |
| CSI500 Beta 显著高于 CSI300 Beta | 中小盘暴露为主，业绩与中证500 同步 |
| 两个 Beta 都 < 0.5，R² 也低 | 风格中性 / 主动管理 / 非股票（如债基），股票基准解释力弱 |
| Alpha（年化）> 5% 且 R² > 0.8 | 在解释充分的前提下仍有显著超额，是真 Alpha 不是风格漂移 |

## 四、学习要点

### 1. Beta 不是总和为 1 的权重

OLS 不强制 $\sum \beta_i = 1$，Beta 可以全部为正且总和 > 1（典型杠杆基金）、可以为负（做空对应基准）。这与"我的基金 70% 跟踪沪深300、30% 跟踪中证500"的语义不同——那需要带约束的回归（如 Lasso + 非负约束 + 和约束），不是无约束 OLS 的输出。

### 2. R² 低不等于因子无效

R² < 0.5 时不要急于得出"基准不解释这只基金"的结论。常见原因：

- **样本太短**：1 年以下的数据，残差占比天然偏高
- **风格漂移**：基金中途换风格，整段回归被平均掉
- **非股票成分**：含债券 / 现金的混合基金，股票基准无法解释非股票部分

### 3. Alpha 的统计显著性未做检验

`fund_style_report()` 只输出 Alpha 点估计，没有给标准误和 t 值。日 Alpha 0.0002 看着大，其实可能 t 值 < 1，统计上和零无差异。严肃使用时应补充 t 检验，本项目作为风格判断辅助工具，没做这一步。

### 4. 分层与解耦

整个模块严格分了三层：

```
quant/data/benchmark.py    数据获取 + 缓存（IO，可能失败）
       ↓
quant/fund/style.py        纯计算（无 IO，可单元测试）
       ↓
dashboard/pages/6.py       展示（用户交互，session_state 缓存）
```

每层职责单一。后续给 `quant/risk/report.py` 接 Beta/Alpha 时，直接复用 `quant/data/benchmark.py` 就行，不必再写一遍 akshare 调用。
