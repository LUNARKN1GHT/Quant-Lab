# 基金持仓建议：系统信号到操作决策的接入设计

## 现状诊断

### 已有的基础设施

| 模块 | 位置 | 功能 |
| :---: | :---: | :---: |
| 仓位建议引擎 | `quant/advisor/position.py` | Regime × 波动率目标 × 宏观景气 → 建议总仓位 |
| 市场状态检测 | `quant/regime/detector.py` | BULL / RANGE / BEAR 三态判断 |
| 宏观景气指数 | `quant/macro/indicators.py` | 综合 PMI / 利率 / M2 等宏观指标 |
| 行业轮动信号 | `quant/sector/rotation.py` | 各行业相对强弱（RS）排名 |
| 基金持仓模块 | `quant/fund/portfolio.py` | 持仓统计、风险指标、风格归因 |
| 基金 Dashboard | `dashboard/pages/10_my_portfolio.py` | 持仓看板，含"投资建议" tab |

### 断层所在

"投资建议" tab 目前只做了技术因子扫描（动量/RSI/均线偏离/布林位置），这是在基金 NAV 序列上的技术分析，和系统其他模块完全脱节：

```txt
系统信号链：Regime → Advisor → [断层] → 用户持仓
                                ↑
                          此处缺少连接
```

具体缺失：

1. **Advisor 输出未接入**：用户不知道今天建议持多少权益仓位
2. **持仓偏差未计算**：现在实际仓位和 Advisor 建议之间的偏差，没有量化
3. **基金无类型区分**：权益基/债基/混合基的仓位建议应该不同，当前一视同仁
4. **风格归因未展示**：`portfolio.py` 里已实现 `style_attribution()`，但 Dashboard 从未调用
5. **定投计划孤立**：定投是固定规则触发，没有利用 Regime 信号判断是否值得加大力度

### 二、Regime + Advisor 信号接入持仓建议

核心思路：把 `compute_position()` 的输出显示在"投资建议" tab 的顶部，作为全局权益仓位的锚点。

**新增 `quant/fund/advisor_signal.py`**

```python
"""将系统 Advisor 输出转换为基金层面的持仓建议"""

import pandas as pd

from quant.advisor.position import compute_position
from quant.config import Config
from quant.regime.detector import Regime


REGIME_LABEL = {
    Regime.BULL.value: ("BULL — 趋势上行", "🟢"),
    Regime.RANGE.value: ("RANGE — 震荡整理", "🟡"),
    Regime.BEAR.value: ("BEAR — 趋势下行", "🔴"),
}

FUND_TYPE_SCALE = {
    # 在 Advisor 建议仓位基础上，不同类型基金的系数调整
    # 权益基直接用 Advisor 仓位；债基在熊市反向加仓
    "equity":   {"BULL": 1.0,  "RANGE": 1.0,  "BEAR": 1.0},
    "balanced": {"BULL": 0.85, "RANGE": 0.85, "BEAR": 0.85},
    "bond":     {"BULL": 0.5,  "RANGE": 0.7,  "BEAR": 1.0},
    "money":    {"BULL": 0.3,  "RANGE": 0.4,  "BEAR": 0.6},
}


def latest_signal(
    close: pd.DataFrame,
    cfg: Config,
    macro_score: pd.Series | None = None,
) -> dict:
    """返回今日最新仓位建议及各层信号分解。

    Returns:
        {
            "regime": "BULL",
            "regime_label": "BULL — 趋势上行",
            "regime_emoji": "🟢",
            "regime_scale": 1.0,
            "vol_scale": 0.85,
            "macro_multiplier": 1.1,
            "position": 0.935,   # 最终建议权益仓位
            "date": Timestamp,
        }
    """
    result_df = compute_position(close, cfg, macro_score)
    latest = result_df.dropna().iloc[-1]
    regime_val = latest["regime"]
    label, emoji = REGIME_LABEL.get(regime_val, (regime_val, "⚪"))
    return {
        "regime": regime_val,
        "regime_label": label,
        "regime_emoji": emoji,
        "regime_scale": latest["regime_scale"],
        "vol_scale": latest["vol_scale"],
        "macro_multiplier": latest["macro_multiplier"],
        "position": latest["position"],
        "date": result_df.dropna().index[-1],
    }


def fund_position_advice(
    signal: dict,
    holdings_df: pd.DataFrame,  # 含 symbol / name / mkt / fund_type 列
    total_capital: float,
) -> pd.DataFrame:
    """对每只持仓基金给出建议仓位和操作方向。

    Args:
        signal: latest_signal() 的返回值
        holdings_df: 持仓明细（需包含 fund_type 列）
        total_capital: 总资金（含现金）

    Returns:
        DataFrame，每行一只基金，含建议仓位比例 / 操作方向 / 偏差金额
    """
    base_position = signal["position"]
    regime = signal["regime"]
    rows = []

    for _, h in holdings_df.iterrows():
        ftype = h.get("fund_type", "equity")
        scale = FUND_TYPE_SCALE.get(ftype, FUND_TYPE_SCALE["equity"]).get(regime, 1.0)
        suggested_weight = base_position * scale

        current_mkt = h["mkt"]
        current_weight = current_mkt / total_capital if total_capital > 0 else 0
        suggested_mkt = total_capital * suggested_weight
        diff = suggested_mkt - current_mkt

        if diff > total_capital * 0.02:
            action = "🟢 建议加仓"
        elif diff < -total_capital * 0.02:
            action = "🔴 建议减仓"
        else:
            action = "⚪ 持有不动"

        rows.append({
            "名称": h["name"],
            "代码": h["symbol"],
            "类型": ftype,
            "当前仓位": current_weight,
            "建议仓位": suggested_weight,
            "偏差金额": diff,
            "操作建议": action,
        })

    return pd.DataFrame(rows)
```

## 实现优先级

| 优先级 | 改进项 | 理由 |
| :---: | :---: | :---: |
| P0 | 接入 Regime + Advisor 信号，展示建议权益仓位 | 这是整个控仓系统的"出口"，必须联通 |
| P1 | 持仓偏差计算 + 操作建议 | 让数字变成可执行的动作 |
| P2 | 风格归因展示（`style_attribution`已实现） | 代码已有，只差 Dashboard 调用 |
| P3 | 定投建议联动 Regime | 提升定投决策质量 |
| P4 | 基金分类字段（fund_type） | 前提基础设施，影响 P1 的准确性 |

## 设计边界与注意事项

### 为什么不直接把股票因子用在基金 NAV 上？

股票因子（IC / 截面动量 / 特质波动率）是在**股票截面**上计算的，需要多只股票同时比较才有意义。把它们用在单只基金的 NAV 时序上，失去了截面比较的维度，退化为普通技术分析。当前 Dashboard 的技术因子扫描（动量/RSI等）在这个框架下是合理的，但要清楚它的局限：

- 它描述的是"这只基金现在便宜不便宜（技术面）"
- 它**不能**描述"应该持有多少权益资产（配置决策）"

这两件事需要不同的工具——后者正是 Advisor 模块的职责。

### 数据依赖

接入 `compute_position()` 需要成分股收盘价宽表（`close`），这在 DuckDB 的 `price_daily` 表中已有，只需在 Dashboard 加载时传入。若数据库未更新到最新，建议先点击数据管理页的更新按钮。
